## Assessment Philosophy

The six problems should deliberately increase in conceptual difficulty.

- **Easy**: Test whether the candidate has reliable programming fundamentals.
- **Medium**: Test whether the candidate can identify and implement non-trivial algorithms.
- **Hard**: Test whether the candidate can derive an efficient solution for unfamiliar constraints and reason about mathematical or constructive properties.

The assessment should NOT reward memorization alone.
- A candidate who submits a partially complete solution but demonstrates strong algorithmic reasoning should receive meaningful credit.
- A candidate who submits copied code but cannot explain the approach should not receive full credit.

---

## Evaluation Criteria

Candidates will be evaluated on the following criteria:

1. **Correctness** — 40%
2. **Algorithm and Complexity** — 25%
3. **Problem-Solving / Reasoning** — 20%
4. **Code Quality** — 10%
5. **Explanation** — 5%

For each problem, evaluators should consider:
- Correctness
- Edge cases
- Time complexity
- Space complexity
- Appropriate data structures
- Ability to explain why the approach works
- Ability to identify limitations of weaker approaches

### Suggested Overall Interpretation

- **85-100**: Strong candidate — highly recommended
- **70-84**: Good candidate — recommend for technical discussion
- **55-69**: Borderline — evaluate through interview and learning ability
- **Below 55**: Not currently ready for team selection

> **Note to Evaluators:** Do not make the numerical score the sole selection criterion. Ensure holistic review of the candidate's logic and approach.
